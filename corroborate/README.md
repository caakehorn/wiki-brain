# `corroborate/` — the corroboration ledger

**What the wiki says, checked against what the messages record.** This
directory holds the record of which dated claims have been put to the message
archive, what came back, and what it changed.

`bin/wiki-corroborate` is the tool. `CLAUDE.md`'s **CORROBORATE** operation is
the protocol. Read the tool's module docstring before touching anything here.

## Why it exists

282,050 first-party messages sit in `raw/`, timestamped to the second, written
at the time by the people involved, with no audience and no thesis. Almost every
page in this wiki was written from something else — a later retelling, an AI
dossier, an operator answer, a memory of a video — and **until 2026-09-06
nothing joined the two.** `bin/mine-messages` could find a string if somebody
thought to look for one. `bin/wiki-crosslink` finds entity mentions a page owes
an edge to. Nothing asked the question that matters most: *the page says this
happened — does the record agree, and what else was said that day?*

The answer is routinely more than the page has.

## The files

| File | What it is |
|---|---|
| `events.jsonl` | **The record.** Append-only, one JSON object per line, never rewritten. |
| `records.json` | A projection of the log. Regenerable (`rebuild`), safe to delete. |
| `SUMMARY.md` | The analysis surface. Generated on every write. |
| `coverage.json` | Per-year row counts for each corpus, and the union. Regenerated by `coverage --write`. |

`wiki/meta/corroboration.md` is the public face, generated by
`bin/wiki-corroborate page`, served on the portal like any other page.

## Three things that will bite

**1. `absent` and `uncovered` are different outcomes and the tool refuses to let
one stand in for the other.** `absent` means the window was read and holds
nothing — a real result, often the cheapest falsifier a page can get.
`uncovered` means the corpus does not reach that date: 2012–2014 hold nothing
and 2022 holds four rows in total, so a 2013 claim can no more be checked here
than falsified. This is the same refusal `bin/wiki-traits` makes between
`silent` and `unreviewed`, and `bin/wiki-claims` between `ended` and `lapsed`.
An instrument that did not run has said nothing.

**2. The ledger cites rows; it never copies them.** A citation is a timestamp, a
direction and a handle. `record` loads the window and **verifies that every
cited row exists** before it will append, so a citation cannot be invented — and
the ledger never becomes a second, drifting copy of the message archive. The
messages themselves stay in `raw/` and are quoted on the pages that argue from
them, the way this wiki has always quoted them.

**3. A record is never edited.** `record --revise <id> --reason` supersedes it
and the log keeps both, exactly as an adjudication or an expiry does. A
corroboration that can be quietly rewritten is worth less than none.

## The gate

`bin/wiki-corroborate check` runs inside `bin/wiki-check`. It reads the
**working diff, not the tree**, and that is what keeps it switched on: 370 pages
carry dated claims nothing has ever checked, and a gate red on all of them would
be disabled inside a week. It fires when a pass writes a date the page did not
already carry, inside coverage, with no record covering it. There is no skip
flag; the way past it is to look, and `--outcome absent` is a legitimate and
complete answer.

Generated pages are exempt, and so is `wiki/meta/` outside `journeys/` — those
dates are repository history, and the instrument for those is the git log
(`bin/wiki-history`), not the message archive.

## ⚠ This is tracked, in a public repository

Like `intake/`, `testimony/` and `claims/`, and by the same operator decision of
2026-08-30. The ledger holds timestamps, handles and one-sentence claims — never
message text — but a handle is a phone number and a claim is about a real
person. To reverse: **make the repository private first, verify it, and only
then** decide whether ignoring these files is still wanted. In that order,
always.
